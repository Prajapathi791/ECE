The hardware underneath

The simulator's ALU is built from a ripple-carry adder, the same way the 8086 does it. Subtraction adds the inverted operand with a carry-in of 1. Every arithmetic flag is read off the carry chain.

Assumptions and limits

      
    
        
  • Memory is one flat 64 KB space. Segment registers are not modelled, so MOV DS, AX is rejected with an explanation.
    • 
        
  • Data defined with DB and DW is placed from address 0200h, in the order it appears.
    • 
        
  • The stack starts at FFFEh and grows down. Going below F000h is a stack overflow fault. Popping an empty stack is an underflow fault.
    • 
        
  • Execution stops after 10,000 steps with a fault, so an accidental endless loop cannot hang the page.
    • 
        
  • The 8086 rules are enforced: no memory-to-memory moves, shift counts of 1 or CL only, no PUSH of an immediate, and byte and word sizes must match.
    • 
        
  • MUL and IMUL set CF and OF. DIV and IDIV leave the flags unchanged, since the real flags are undefined after them. Divide by zero and quotient overflow raise a divide error.
    • 
        
  • Instruction encoding, timing (clock cycles), interrupts other than program exit, string instructions and I/O ports are outside the scope of this simulator.
    • 
      


      
Reproducing the AI/DS results

      
Datasets come from a small seeded generator (mulberry32). The seed, the sample count and the workload fully determine the data, the assembly program and the expected answer. The AI/DS lab can copy the dataset as CSV, and the Tests tab can copy every test case as JSON.
